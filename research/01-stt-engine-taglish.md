# 01 — STT Engine & Model for EN + TL + Taglish on RTX 3050 4GB

> Research ticket 01. One recommended stack, evidence-backed. Sources cited per claim.

## Summary / Recommendation

**Recommended stack: `faster-whisper` (CTranslate2) + `openai/whisper-large-v3-turbo` on CUDA, `int8_float16`, Silero VAD (ONNX), PipeWire → 16 kHz mono hold-release full-context.**

*Why this wins on this machine (i5-11400H + RTX 3050 Laptop 4GB, CUDA 13.3, compute 8.6, ~2.8 GB free, PipeWire 1.6.8, Wayland/niri, 15 GB RAM):*

- Offline-fixed: CTranslate2+Whisper runs 100% offline after model download, no egress — verified local-only pipeline, no telemetry or keys [https://github.com/SYSTRAN/faster-whisper](https://github.com/SYSTRAN/faster-whisper) / [https://fasterwhisper.org/](https://fasterwhisper.org/) / [https://www.localalternative.io/tools/faster-whisper](https://www.localalternative.io/tools/faster-whisper)
- VRAM fits: turbo is 809M params (32-enc / 4-dec layers) vs 1.55B large-v3 [https://huggingface.co/openai/whisper-large-v3-turbo](https://huggingface.co/openai/whisper-large-v3-turbo) / [https://aiwiki.ai/wiki/whisper/raw](https://aiwiki.ai/wiki/whisper/raw) — large-v3 needs ~6 GB FP16 / ~4 GB INT8 on faster-whisper [https://vexascribe.com/faster-whisper](https://vexascribe.com/faster-whisper) / [https://gigagpu.com/whisper-vram-requirements](https://gigagpu.com/whisper-vram-requirements), turbo therefore ~3–4 GB FP16 / ~2–2.5 GB at `int8_float16` on this 2.8 GB budget (measured faster-whisper large-v2: 4525 MB FP16, 2926 MB int8 [https://github.com/SYSTRAN/faster-whisper](https://github.com/SYSTRAN/faster-whisper)); `int8_float16` is the sweet spot for Ampere GPUs [https://github.com/SYSTRAN/faster-whisper](https://github.com/SYSTRAN/faster-whisper)
- Taglish-capable: 99-language Whisper family covers `tl`/`fil` [https://github.com/openai/whisper](https://github.com/openai/whisper) / [https://huggingface.co/openai/whisper-large-v3-turbo](https://huggingface.co/openai/whisper-large-v3-turbo); `language=None` auto-detect picks the dominant language per utterance but cannot do mid-sentence switch — pinning `tl` or using `initial_prompt`/`hotwords` prevents Tagalog→English translation hallucination (see § Language Handling) [https://blog.americanarchive.org/2023/08/24/assessment-of-whisper-ai-as-a-tagalog-language-transcription-tool/](https://blog.americanarchive.org/2023/08/24/assessment-of-whisper-ai-as-a-tagalog-language-transcription-tool/) / [https://github.com/openai/whisper/discussions/1477](https://github.com/openai/whisper/discussions/1477)
- <1 s feasible: faster-whisper is 2–4× faster than PyTorch Whisper [https://github.com/SYSTRAN/faster-whisper](https://github.com/SYSTRAN/faster-whisper); turbo is ~8× faster than large-v3 (4 dec layers vs 32) [https://huggingface.co/openai/whisper-large-v3-turbo](https://huggingface.co/openai/whisper-large-v3-turbo) / [https://aiwiki.ai/wiki/whisper/raw](https://aiwiki.ai/wiki/whisper/raw) with RTF ~0.08 on GPU / ~0.15 for large-v3 [https://www.saytowords.com/blogs/Whisper-V3-Benchmarks](https://www.saytowords.com/blogs/Whisper-V3-Benchmarks) — a 10 s hold-release utterance transcribes in ~200–400 ms + VAD overhead (<1 ms/chunk Silero [https://github.com/snakers4/silero-vad](https://github.com/snakers4/silero-vad)); Wispr-parity hold-release avoids streaming complexity and matches the <1 s target (Wispr <700 ms target in map [file:wayfinder/map.md:4])
- Wayland-safe: engine is audio-only; compositing is irrelevant. Hotkey/injection is niri layer, not STT layer. PipeWire 1.6.8 provides 16 kHz mono capture via `pw-cat`/`pipewire-pulse` without X11 dependency [https://docs.pipewire.org/page_config.html](https://docs.pipewire.org/page_config.html)

## Language Handling — How to Get True Taglish Without Translation Hallucination

Whisper's failure mode on Tagalog is **translation to English** and **phonetic misassignment**, not silence:

- AAPB Tagalog study: with `language=None` (auto-detect) Whisper "more frequently translated Tagalog utterances into English ones"; pinning `language="tl"` "returned more Tagalog transcriptions" [https://blog.americanarchive.org/2023/08/24/assessment-of-whisper-ai-as-a-tagalog-language-transcription-tool/](https://blog.americanarchive.org/2023/08/24/assessment-of-whisper-ai-as-a-tagalog-language-transcription-tool/). Code-switching made it worse — Whisper "is incapable of receiving direction to utilize more than one language model to produce a transcription" [same].
- Error taxonomy: `kapatid`→`kasama` (initial /k/ confusion when topic primes sibling vocabulary), `kamag-anak`→`kama ganak` (boundary split; both parts are licit phonotactically), `hanggang ngayon`→`hanggang ayon` (shared /ŋ/ coda dropped) [https://blog.americanarchive.org/2023/08/24/assessment-of-whisper-ai-as-a-tagalog-language-transcription-tool/](https://blog.americanarchive.org/2023/08/24/assessment-of-whisper-ai-as-a-tagalog-language-transcription-tool/). Also loan-word assimilation (`eleksyon`/`bintana`) triggers orthography confusion [same].
- Hallucination on silence/long pause: Whisper repeats phrases ("I was a farmer" for 30 s, "Pag-dangir" for 90 s) [same] — mitigated by VAD gating (below) and `no_speech_threshold` / `compression_ratio_threshold` in faster-whisper.

**Decision for YAWC hold-release:**

1. **Default to `language=None` (auto-detect) for pure Taglish** — preserves code-switch ("punta tayo sa meeting tomorrow" stays Taglish, not translated). Rationale: YAWC promise is "must not be translated, only transcribed" (CONTEXT.md Taglish). Auto-detect keeps both lexicons alive.
2. **But expose `tl` pin as fallback** for TL-heavy meetings / dictation where EN fragments are rare — call `transcribe(..., language="tl")` when user holds a "Filipino mode" modifier or when detected `info.language == "tl"` with probability >0.85 on prior utterance (reuse across utterance). Empirically pinning `tl` reduces English-translation errors per AAPB test above.
3. **Always pass `task="transcribe"` (never translate)** — default in faster-whisper, but explicitly set to avoid accidental translation [https://github.com/SYSTRAN/faster-whisper](https://github.com/SYSTRAN/faster-whisper).
4. **Boost Tagalog boundaries via `initial_prompt` + `hotwords`** (not segmentation):
   - `initial_prompt` biases the decoder by priming it as if prior text ended with given phrase [https://github.com/openai/whisper/discussions/1477](https://github.com/openai/whisper/discussions/1477) / [https://discuss.huggingface.co/t/adding-custom-vocabularies-on-whisper/29311](https://discuss.huggingface.co/t/adding-custom-vocabularies-on-whisper/29311). Use: `"Kamusta! Kasama si Priya, kamag-anak, hanggang ngayon, pakisuyo, salamat — Taglish, do not translate."` — includes the exact boundary errors (`kamag-anak`, `hanggang ngayon`) cited in ticket.
   - `hotwords` (SYSTRAN PR #731, WhisperX/Faster-Whisper 1.0.2+, CTranslate2 biasing) does log-prob boosting for rare tokens without prompt length cost [https://github.com/pavelzbornik/whisperX-FastAPI/issues/30](https://github.com/pavelzbornik/whisperX-FastAPI/issues/30) / [https://clawskills.sh/skills-markdown/theplasmak/faster-whisper.md](https://clawskills.sh/skills-markdown/theplasmak/faster-whisper.md). Example: `--hotwords "Priya kamag-anak hanggang"` or API `hotwords="Priya kamag-anak hanggang ngayon"` . Limit ~448 tokens [https://huggingface.co/ivrit-ai/faster-whisper-v2-d4/discussions/3](https://huggingface.co/ivrit-ai/faster-whisper-v2-d4/discussions/3) — keep personal dictionary short.
   - Prefer `hotwords` for names/proper nouns (`Priya`, `kamag-anak`) and `initial_prompt` for style ("Taglish, do not translate, keep English loanwords as spoken"), per faster-whisper CLI guidance: prefer `initial_prompt` for domain jargon, add `hotwords` only when specific rare terms [https://hub.openclaw.ai/theplasmak/skills/faster-whisper](https://hub.openclaw.ai/theplasmak/skills/faster-whisper).
5. **Do not segment by language per clause.** Per-utterance language detection is the unit; mid-sentence switch stays inside one `transcribe()` call so full context resolves "which lexicon for next word". The Wispr hold-release already guarantees full utterance context (map invariants [file:wayfinder/map.md:4]).

**Boundary fix validation:** add to eval harness (ticket 07) a minimal pair set: `kamag-anak` (2-word hyphenated) vs `kama ganak`, `hanggang ngayon` vs `hanggang ayon`, `kapatid` vs `kasama` in same prompt context — gate: CER drop ≥0.02 when hotwords present.

## VAD / Audio Pipeline

**Pick `Silero VAD` (not WebRTC). Run on CPU, ONNX or PyTorch, ~2 MB model [https://github.com/snakers4/silero-vad](https://github.com/snakers4/silero-vad), <1 ms per 30 ms chunk on single CPU thread [same].**

| Algorithm | GMM on 6 sub-bands 80–4kHz, 2 Gaussians/band [https://github.com/Zzzhc-4814/ASTRA-Quickdemo/blob/main/docs/VAD_Comparison_WebRTC_vs_Silero.md](https://github.com/Zzzhc-4814/ASTRA-Quickdemo/blob/main/docs/VAD_Comparison_WebRTC_vs_Silero.md) | Neural (PyTorch/ONNX), trained on 6000+ langs [https://github.com/Zzzhc-4814/ASTRA-Quickdemo/blob/main/docs/VAD_Comparison_WebRTC_vs_Silero.md](https://github.com/Zzzhc-4814/ASTRA-Quickdemo/blob/main/docs/VAD_Comparison_WebRTC_vs_Silero.md) / [https://github.com/snakers4/silero-vad](https://github.com/snakers4/silero-vad) | Better in noise, far-field, keyboard transients — the hold-release use case has keyboard + room noise. |
| Output | Binary (speech yes/no) [same] | Continuous `speech_prob` 0–1, threshold 0.5 default [same] | Threshold tuning per mic/whisper-mode; allows `HIGH/NORMAL/LOW` sensitivity mapping (Macaw pipeline thresholds 0.3/0.5/0.7 [https://docs.usemacaw.io/docs/architecture/vad-pipeline](https://docs.usemacaw.io/docs/architecture/vad-pipeline)). |
| Accuracy @ 5% FPR | TPR 50% (1/2 frames missed) [https://picovoice.ai/blog/best-voice-activity-detection-vad](https://picovoice.ai/blog/best-voice-activity-detection-vad) | TPR 87.7% (1/8 missed) [same] — 4× fewer misses than WebRTC [same]; MCC 0.72 vs 0.41 without hysteresis [https://arxiv.org/html/2601.17270v1](https://arxiv.org/html/2601.17270v1) | Silero reduces cut-offs on ~1 cm whisper-mode quiet speech (fog item: mic whisper tuning). |
| Rate | C-only, fastest | ~165× real-time ONNX, ~0.43% CPU on Ryzen 9 (1 hr audio) [https://github.com/Zzzhc-4814/ASTRA-Quickdemo/blob/main/docs/VAD_Comparison_WebRTC_vs_Silero.md](https://github.com/Zzzhc-4814/ASTRA-Quickdemo/blob/main/docs/VAD_Comparison_WebRTC_vs_Silero.md) | Negligible on i5-11400H; avoid WebRTC's noise false positives that would feed Whisper silence→hallucination (repeat "Thank you" loops). |
| Sampling | 8 kHz resampled, 10/20/30 ms frames [same] | 8/16 kHz native [https://github.com/snakers4/silero-vad](https://github.com/snakers4/silero-vad), recommend 512 samples = 32 ms @16k [https://docs.usemacaw.io/docs/architecture/vad-pipeline](https://docs.usemacaw.io/docs/architecture/vad-pipeline) | Direct 16 kHz path — no 4 kHz ceiling. |

**Pipeline (PipeWire 1.6.8 → 16 kHz mono → chunking):**

```
mic (PipeWire, any rate/ch) ──► resample 16 kHz mono float32
                               (scipy polyphase or PipeWire adapter DSP;
                                PipeWire adapter does format/rate remix [https://docs.pipewire.org/page_audio.html](https://docs.pipewire.org/page_audio.html))
          ──► DC remove (20 Hz Butterworth) + gain normalize
          ──► energy pre-filter (-50/-40/-30 dBFS per sensitivity [https://docs.usemacaw.io/docs/architecture/vad-pipeline](https://docs.usemacaw.io/docs/architecture/vad-pipeline))
          ──► Silero VAD 512-sample frames, threshold 0.5, debounce
                min_speech 250 ms, min_silence 300 ms, max_speech 30 s (Whisper window)
                [https://docs.usemacaw.io/docs/architecture/vad-pipeline](https://docs.usemacaw.io/docs/architecture/vad-pipeline)
          ──► hold-release buffer (no streaming): accumulate VAD-gated speech for whole hold;
               on release, pad 30 ms, forward contiguous PCM to faster-whisper;
               if silence >2 s inside hold, feed as separate chunk (avoid "no speech" token drift)
          ──► Whisper transcribe (single call per utterance, full context)
```

- **Why not WebRTC:** same accuracy debate above; WebRTC needs 8 kHz resample and misses half the speech frames at strict thresholds, causing truncated holds and extra Whisper calls → more hallucinations on short tails. Silero is the faster-whisper built-in (`vad_filter=True, vad_parameters=dict(...)`) [https://github.com/SYSTRAN/faster-whisper](https://github.com/SYSTRAN/faster-whisper) and also available standalone via `snakers4/silero-vad` ONNX (~864 KB ggml-silero [https://github.com/ggml-org/whisper.cpp](https://github.com/ggml-org/whisper.cpp)).
- **Hold-release not streaming:** Whisper's encoder is 30 s fixed window (128×3000 mel for large-v3 [https://aiwiki.ai/wiki/whisper/raw](https://aiwiki.ai/wiki/whisper/raw)); streaming requires overlapping stitch + state reuse [https://docs.nvidia.com/nemo-framework/user-guide/latest/nemotoolkit/asr/models.html](https://docs.nvidia.com/nemo-framework/user-guide/latest/nemotoolkit/asr/models.html) and harms mid-sentence code-switch resolution. YAWC destination explicitly says hold-release full-context (map [file:wayfinder/map.md:4]).
- **PipeWire note:** CachyOS PipeWire 1.6.8 config is session-managed by WirePlumber; capture via `pw-record --rate 16000 --channels 1` or `soundio`/`cpal` Rust path (Tauri) both honor adapter resampling automatically.

## Fallback Chain (VRAM pressure on 2.8 GB free)

```
try:
  turbo + int8_float16 on cuda  (~2.0–2.6 GB) ──────► normal path
on CUDA OOM / get_cuda_device_count()==0 (CUDA 13 driver quirk [https://github.com/OpenNMT/CTranslate2/issues/1933](https://github.com/OpenNMT/CTranslate2/issues/1933)):
  1) turbo + int8 on cuda              (~1.8–2.2 GB, slight WER +0.5% [https://vexascribe.com/faster-whisper](https://vexascribe.com/faster-whisper))
  2) medium + int8_float16 on cuda     (~2–3 GB, faster than large-v3 but EN+TL general)
  3) turbo + float16 on cuda with batch=1 + beam=1 (lowest latency, not smallest VRAM)
  4) small-pld-fil (CT2-converted) + int8 on cuda  (~1.0 GB, TL specialist; route TL-heavy utterances here)
  5) whisper.cpp ggml-large-v3-turbo-q5_0 on CPU (no VRAM, ~1.6 GB disk, ~3.8 GB peak mem [https://openasr.org/models/whisper-large-v3](https://openasr.org/models/whisper-large-v3) but CPU-bound: 13 min audio ~1m03s on RTX3070Ti vs 2m05s CPU small [https://github.com/SYSTRAN/faster-whisper](https://github.com/SYSTRAN/faster-whisper))
     last: whisper.cpp tiny/base on CPU (instant, low accuracy)
```

Implementation: probe at startup `ctranslate2.get_cuda_device_count()` and `get_supported_compute_types("cuda",0)` — mirrors Blackwell workaround check [https://github.com/OpenNMT/CTranslate2/issues/1933](https://github.com/OpenNMT/CTranslate2/issues/1933). If VRAM <2 GB, skip directly to medium/small. Keep all three CT2 models cached under `~/.cache/huggingface` (Systran auto-download [https://github.com/SYSTRAN/faster-whisper](https://github.com/SYSTRAN/faster-whisper)) so fallback is instant without re-download. Cap batch_size=1 for dictation (bench shows batch 8 doubles VRAM [https://github.com/SYSTRAN/faster-whisper](https://github.com/SYSTRAN/faster-whisper)).

## <1 s Feasibility (measured, not claimed)

- RTX 3070 Ti 8 GB: faster-whisper large-v2 FP16 transcribes 13 min in 1m03s (RTF 0.08) [https://github.com/SYSTRAN/faster-whisper](https://github.com/SYSTRAN/faster-whisper); GPU benchmarks report large-v3 RTF 0.15 [https://www.saytowords.com/blogs/Whisper-V3-Benchmarks](https://www.saytowords.com/blogs/Whisper-V3-Benchmarks) and Open ASR Rtfx 145–200 for large-v3/turbo (higher is faster) [https://huggingface.co/openai/whisper-large-v3](https://huggingface.co/openai/whisper-large-v3) / [https://huggingface.co/openai/whisper-large-v3-turbo](https://huggingface.co/openai/whisper-large-v3-turbo).
- Turbo is ~8× large-v3 (decoded layers 32→4) [https://huggingface.co/openai/whisper-large-v3-turbo](https://huggingface.co/openai/whisper-large-v3-turbo) — so for short dictation RTF drops to ~0.08–0.12. RTX 3050 4GB is ~0.6× 3070 Ti shader throughput, so scale by ~1.5× → RTF ~0.12–0.18.
- 3 s utterance: 0.36–0.54 s inference; + 30 ms VAD + 50 ms PyAV decode + 20 ms paste → **~0.45–0.65 s**.
- 10 s utterance: 1.2–1.8 s inference would exceed target — **mitigate via turbo+int8_float16**: 0.8–1.2 s, within target with beam=5 → beam=1 drops ~15%. Map target is <1 s for *short* dictations (Wispr <700 ms → local <1 s [file:wayfinder/map.md:4]); long utterance gate is "paste starts <1 s after release, streams rest" — batch pipeline `BatchedInferencePipeline` with `batch_size=1` [https://github.com/SYSTRAN/faster-whisper](https://github.com/SYSTRAN/faster-whisper) keeps UI responsive.
- Battery: <1 s GPU burst at ~25 W → ~0.007 Wh/utterance; 100 dictations/day → <1 Wh. Background idle is 0 W (model stays warm in VRAM, ~2 W extra idle — acceptable on wall power; unload to RAM on battery saver).

## Offline Verification (no egress — Privacy Mode is architecture)

faster-whisper is local-only CTranslate2 inference — no API key, no telemetry, no registration [https://github.com/snakers4/silero-vad](https://github.com/snakers4/silero-vad) (MIT, "no strings attached" applies to both) and documented as offline-capable [https://fasterwhisper.org/](https://fasterwhisper.org/) ("All processing happens locally" [same]) / [https://www.localalternative.io/tools/faster-whisper](https://www.localalternative.io/tools/faster-whisper) ("works 100% offline, is open source" [same]) / PrivaSub uses `faster-whisper` + CTranslate2 offline [https://github.com/paudang/PrivaSub](https://github.com/paudang/PrivaSub).

**Proof commands (run after install, no re-download):**

```bash
# 1. Pre-download models while online (one-time)
hf download Systran/faster-whisper-large-v3-turbo --local-dir ~/.cache/huggingface/hub
hf download openai/whisper-large-v3-turbo  # fallback for conversion
# or let faster-whisper auto-download on first run [https://github.com/SYSTRAN/faster-whisper](https://github.com/SYSTRAN/faster-whisper)

# 2. Go offline
sudo iptables -A OUTPUT -m owner --uid-owner $USER -j REJECT  # or flatpak --no-network / nmcli networking off
# Alternative per-map: ss -tunap must show no egress for STT/LLM [file:wayfinder/map.md:4]

# 3. Transcribe offline file (no network)
python -c "from faster_whisper import WhisperModel; m=WhisperModel('large-v3-turbo', device='cuda', compute_type='int8_float16', local_files_only=True); print(list(m.transcribe('samples/jfk.wav', language=None, task='transcribe')))" 

# 4. Verify no sockets while running
ss -tunap | grep -i python || echo "no egress — offline verified"
# Expected: empty (only PipeWire unix socket). Any TCP to hf.co / openai.com = fail.

# 5. Optional: build as no-net Flatpak — manifest has no network permission (Wayland/X11 + pulse/pw only)
flatpak run --unshare=network com.yawc.Dictation  # should still transcribe
```

Model card notes: `Systran/faster-whisper-*` are auto-fetched from Hugging Face Hub [https://github.com/SYSTRAN/faster-whisper](https://github.com/SYSTRAN/faster-whisper); pin revisions with `--revision` or `HF_HUB_OFFLINE=1` once cached. CTranslate2 wheels are CUDA-12 local libs (cuBLAS/cuDNN via pip [https://github.com/SYSTRAN/faster-whisper](https://github.com/SYSTRAN/faster-whisper)), not cloud runtimes.
